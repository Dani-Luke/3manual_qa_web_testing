# SauceDemo — Manual Web UI Testing

## Overview (Обзор)

Учебный проект по ручному тестированию Web UI приложения SauceDemo.

В рамках проекта я провел функциональное тестирование пользовательского сценария интернет-магазина: авторизация, работа с каталогом товаров, сортировка, просмотр товаров, корзина, оформление и завершение заказа.

Проект выполнил в учебных целях для формирования портфолио Junior Manual QA и не является коммерческим опытом работы.

## Objective (Цель)

Проверить работоспособность пользовательского функционала SauceDemo с точки зрения конечного пользователя, выявить функциональные и визуальные дефекты, а также подготовить основные QA-артефакты.

## Scope (Область тестирования)

### In Scope (Входит в область тестирования)

* Authentication — Аутентификация
* Logout — Выход из системы

* Product Sorting — Сортировка товаров

* Remove from Cart — Удаление товара из корзины
* Cart — Корзина
* Checkout — Оформление заказа
* Checkout field validation — Валидация полей оформления заказа
* Order Overview — Обзор заказа
* Price calculation — Расчёт стоимости заказа
* Order Completion — Завершение заказа
* Return to Products — Возврат к товарам
* PDF Receipt — PDF-чек
* Основные элементы пользовательского интерфейса

## Test Approach (Подход к тестированию)

В ходе тестирования использовал:

* функциональное тестирование;
* позитивные и негативные сценарии;
* проверка валидации полей;
* проверка навигации;
* проверка взаимодействия компонентов;
* сравнение данных между различными страницами;
* проверка расчёта стоимости заказа;
* исследовательское тестирование отдельных функций;
* DevTools для анализа элементов интерфейса.

## Test Users (Тестовые пользователи)

В ходе тестирования использовал следующие пользователи SauceDemo:

* `standard_user`
* `problem_user`
* `error_user`

Различия в поведении приложения для разных пользователей также учитывались при поиске дефектов.

## Test Design (Тест-дизайн)

В рамках проекта применил техники тест-дизайна:

Equivalence Partitioning (разбиение на классы эквивалентности) для анализа поведения полей Checkout.

Boundary Value Analysis (анализ граничных значений) для полей SauceDemo не применялся, поскольку для них не были подтверждены конкретные минимальные и максимальные ограничения.

Дополнительные проверки формата вводимых данных были проведены как исследование фактического поведения приложения. Наблюдения не классифицировались как дефекты без подтверждённых требований к допустимому формату данных.

Для полей Checkout в SauceDemo не были придуманы собственные ограничения длины или формата, если они не были подтверждены требованиями приложения. Поэтому соответствующие наблюдения были зафиксированы как фактическое поведение, а не как дефекты.
